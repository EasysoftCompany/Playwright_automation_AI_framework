Review the test code against the conventions in `CLAUDE.md` and the scenarios in
`TEST_PLAN.md`. The bar is a senior QE reviewer.

Scope: **$ARGUMENTS** — if empty, review the current diff against the base branch
(`git diff origin/main...HEAD`); if there is no diff, review the whole suite.

## Check in this order

1. **Traceability** — does every test reference a valid scenario ID from
   `TEST_PLAN.md`? List orphan tests. List plan scenarios marked as automated
   that have no implementation.
2. **Assertion strength** — would each test still pass if the feature were
   broken? Flag tautological, missing, or overly permissive assertions.
3. **Locator strategy** — `getByRole` / `getByLabel` first. Flag CSS selectors,
   XPath, `nth-child`, and `getByTestId` used without a justifying comment.
   (The `[contenteditable="true"]` fallback on the Step 3 editor is documented
   and allowed.)
4. **Flakiness** — `waitForTimeout` / sleeps, unawaited promises, race
   conditions, order-dependent or state-sharing tests.
5. **AI-feature awareness** — Step 3 content is generated by Luna and is
   **non-deterministic**. Flag ANY exact-text assertion, snapshot, or keyword
   match on that content. Property-based assertions are required.
6. **Secrets** — any hardcoded or logged credential is a Critical finding.
   This is a public repository.
7. **Honesty** — does each test title describe what is actually asserted?

## Output format

- One verdict line: `APPROVE` or `NEEDS WORK`
- Findings grouped by severity: **Critical** / **High** / **Minor**
- Each finding: file:line, what is wrong, and a concrete fix
- Be direct and specific. Do not praise. If the code is clean, say so in one
  line rather than inventing findings.
