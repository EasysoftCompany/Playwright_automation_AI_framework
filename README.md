# Newsela QE Assessment — Assignment Creation Workflow

Playwright + TypeScript automation framework for the Newsela assignment creation
flow, built with the Page Object Model pattern.

📋 **Start with [TEST_PLAN.md](TEST_PLAN.md)** — scope, risk-based scenario
selection, the Step 3 (student prompt) deep-dive analysis, and the design
decisions behind this framework.

```

│   ├── LoginPage.ts
```

## Three layers of AI in this repo

This project sits at the intersection of AI and quality engineering in three
distinct ways — deliberately, because they are different problems:

**1. AI writes tests (assisted authoring).** Page objects, fixtures and config
were scaffolded with AI assistance. The design work — scenario selection, risk
analysis, locator strategy — is human. AI generates volume; the engineer decides
what the business actually needs.

**2. An AI agent reviews the tests (agentic CI).** `CLAUDE.md` encodes this
repo's conventions, and Claude Code enforces them on every PR: traceability to
the test plan, assertion strength, locator strategy, flakiness, and — critically
— that no test asserts exact text on AI-generated content. Conventions are
human-authored; enforcement is automated.

The review criteria live in `.claude/commands/review-tests.md`, not inline in
the workflow, so the exact same command runs locally (`/review-tests`) and in
CI. Prompts are versioned artifacts reviewed in PRs like any other code. The
agent runs with least privilege — read and analyze only, no write or execute.

**3. The product under test is an AI feature (AI validation).** Step 3's prompt
is generated by "Luna". Non-deterministic output breaks the classic assertion
model, so the suite asserts *properties* (present, editable, persistent, changed
after regenerate, guardrail visible) instead of exact text. See TEST_PLAN.md §4.

## Setup

Requirements: Node.js 18+

```bash
npm ci
npx playwright install --with-deps chromium
cp .env.example .env    # then fill in the provided demo credentials
```

Credentials are read from environment variables and are **never committed**
(`.env` is git-ignored). In CI they are injected via GitHub Secrets
(`NEWSELA_USERNAME`, `NEWSELA_PASSWORD`).

## Run

```bash
npm test              # full suite, headless
npm run test:happy    # happy path only (TC-01)
npm run test:headed   # watch the browser
npm run test:ui       # Playwright UI mode
npm run report        # open the HTML report
```

The happy-path test prints the captured assignment link to stdout:

```
✅ Assignment link: https://...
```

## CI

GitHub Actions runs the suite on every push/PR (`.github/workflows/e2e.yml`):
single worker (shared demo account), retry with trace-on-first-retry, and the
HTML report + traces uploaded as artifacts for failure triage.

## Working with the agent

```bash
npm install -g @anthropic-ai/claude-code
claude mcp add playwright npx @playwright/mcp@latest   # browser control
claude                                                 # interactive session
```

Then, inside the session:

```
/explore-flow                 # verify locators against the live app
/implement-scenario S3-04     # implement a plan scenario under repo conventions
/review-tests                 # the same review CI runs on every PR
```

Headless (the CI shape):

```bash
claude -p "/review-tests" --allowedTools "Read,Grep,Glob"
```

## Design decisions (summary — full rationale in TEST_PLAN.md §5)

- **Accessibility-first locators** (`getByRole`/`getByLabel`; no CSS/XPath)
- **Zero locators in tests** — everything through page objects; tests read as
  the teacher's journey
- **The 5-step modal is one page object** with step methods, not five classes —
  it's a single component with wizard state
- **No sleeps** — auto-waiting and web-first assertions only
- **Independent tests** — each run creates its own data; no shared state
- **AI-assisted scaffolding, human-designed strategy** — scenario selection,
  risk analysis and locator strategy are the design work
